# Repo Instructions

## Product charter

Ergonomic still-image transforms on NetVips. It is not an image-processing framework. See `README.md`.

- The primary public API is `ImagePipeline`: a reusable ordered fluent specification ending in sync `Run(source, destination)` or `RunAsync` for streams that need async I/O. Auto-orient is a default preamble. Stages preserve caller order and compile into one lazy NetVips graph with a single encode. `ImageTransforms.Resize`, `ImageTransforms.Rotate`, and `ImageTransforms.Crop` remain thin shortcuts that compile into a pipeline. The positional resize overload fits inside a box (`ResizeMode.Fit`) and returns the written size. Omit the size to keep the source size.
- Fluent stages use Create-style configure lambdas: `Create(s => s.AutoOrient(...).SourceAlpha(...))`, `.Resize(..., mode, r => r.Aspect(...).Focus(...).Enlarge(...).Canvas(...))`, `.Rotate(..., r => r.Trim(...).Expand().Aspect(...).Canvas(...))`. Resize modes are `Fit`, `Pad`, `Crop`, or `Stretch`. Mode picks size policy: `Fit` is at most the frame (one side may be short); `Pad`, `Crop`, and `Stretch` always write the frame when both dimensions are set. `ImageCanvas` is paint only (letterbox bars on `Pad`, underfill / focus remainders on `Crop`; default transparent). `Fit` and `Stretch` reject a canvas. Canvas on a rotation requires `Expand` (it does not convert `Trim` to `Expand`). Do not put floating `.Aspect` / `.Focus` / `.Canvas` / `.Trim` on the pipeline — they are not stages. `.Crop(x, y, width, height)` extracts an explicit relative rectangle on the upright image (fractions from 0 to 1; positive area; stays inside) — that stage is not `ResizeMode.Crop`. Source admission defaults to auto-orient on and source alpha preserve. Metadata policy stays on `ImageEncoding`. Keep the three alpha knobs separate: (1) `AlphaBehavior` / `SourceAlpha` resolves source-pixel transparency before geometry; (2) `ImageCanvas` is the plate under pad gaps, crop underfill / focus remainders, and expand corners — solid and checkerboard plates also show through preserved content alpha; `Transparent` invents empty gaps only; `Checkerboard` always builds a full-frame preview plate; (3) `AlphaFallbackColor` on encodings that cannot store alpha (`ImageEncoding.Jpeg`) flattens whatever remains at encode time. A canvas does not replace the fallback. Output encoding is `.Encoding(ImageEncoding)` where each format type only exposes valid options (quality on JPEG/AVIF/HEIC; `WebPCompression` lossy-or-lossless on WebP; not on PNG/GIF/TIFF). Shortcuts such as `.EncodingWebP(quality)` and `.EncodingWebP(WebPCompression.Lossless)` are allowed. `ImageTransforms` shortcuts take the same `ImageEncoding`. Do not add a general filter graph, text, watermarks, face/object detection, or a standalone blur. Edge-pixel extension, if it returns, is a canvas, not a resize mode.
- `ImageSize` is a width and height. `XS` is 144×144, `S` 288×288, `M` 576×576, `L` 1008×1008, `XL` 2016×2016, `XXL` 4032×4032. `Thumbnail` is `S`. `Preview` is `L`. A named size is only the frame. It does not change mode, canvas, metadata, or encode. `ImagePresets.ThumbnailWebP` / `PreviewWebP` are pipelines built from the same primitives.
- `ImageRotation.Clockwise` and `CounterClockwise` take a non-negative angle in degrees. `Clockwise(90)` is the exact quarter turn; there is no separate quarter-turn property. `RotationBounds` defaults to `Expand`, the smallest axis-aligned rectangle around the rotated source. New corners use `ImageCanvas` and default to transparent. `Trim` (on rotate configure) is the largest centered axis-aligned rectangle inside the rotated source. An `ImageAspectRatio` on a trim is that rectangle, not a second pad. Manual rotation runs after auto-orient and clears the orientation tag. Do not add a deskew detector or a focus box on the trim. Do not expose a public stage/plugin model for external analysis in MVP.
- The MVP is this package alone. Do not add a companion package, a blurred canvas, or other content-generated operations.
- `ImageTransforms.Identify(Stream)` returns layered `ImageMetadata` from `jaytwo.Ergonomics.Images.Metadata`: typed `Structure` (stored size, visual size after orientation swap, format, alpha, bands, orientation, page count), bags for EXIF (`Ifd0`–`Ifd4` typed IFD objects with common-tag properties and keyed lookup for arbitrary tags, raw values; IFD0 main image, IFD1 thumbnail, IFD2 EXIF sub-IFD, IFD3 GPS, IFD4 interoperability), XMP (opaque XML), IPTC (presence only), and ICC (`ColorProfile.Present`), plus top-level convenience properties (`DateTaken`, `Gps`, `CameraMake`/`CameraModel`) that read those IFDs. Sync stream-in only; read-only (not an EXIF editor). Canvas, source alpha, and encode alpha fallback stay separate (see the three-knob rule above).
- Geometry is in visual pixels. Auto-orientation is on unless the caller turns it off on `Create` / option bags (`AutoOrient = false`).
- Upscale follows `enlarge`, which defaults to false. Pass `r.Enlarge(true)` on resize configure, or `enlarge: true` on the bag. `ResizeMode.Stretch` always writes the requested size and ignores enlarge.
- The default metadata policy is `PreserveColorProfileOnly`.
- Stream in, stream out. Do not add APIs that require `byte[]`.
- Do not take a dependency on `NetVips.Native` from the library project. Tests may, behind `UseBundledLibVips`.
- Do not redistribute an HEVC encoder or decoder. HEIC works only when the host libvips/libheif stack has one.
- No fake async around libvips. Native encode stays synchronous. `RunAsync` bridges async source/destination streams with pipes and wires `CancellationToken` to NetVips kill; prefer sync `Run` when both streams allow sync I/O.
- Caching, HTTP, object storage, and thumbnail persistence stay in the application.

## Code style

- File-scoped namespaces. Private fields use an underscore prefix.
- Public surface stays small. Implementation types are `internal`.
- Match the sibling repos: StyleCop warnings are errors, nullable is on, XML docs on the public API.
